## 3. Hero block — IMPORTANT, DO NOT BREAK

The hero went through ~6 rounds of iteration before landing. **Do not change the structure casually.** Final working approach:

**Two layers in the `.hero` section:**
1. `<img src="assets/hero/hero-illustration.svg">` inside `.hero-illustration` (z-index 0, absolute inset:0, object-fit:cover)
2. `<svg viewBox="0 0 1440 800">` cord layer inside `.hero-cord-layer` (z-index 1)
3. `.hero-inner` text content on top (z-index 2)

The SVG illustration is `Frame 2117131439 (3).svg` from Figma with the **cord path stripped** (the line containing `stroke="#E4572E"`). Stripped via `sed '/E4572E/d'`.

The cord SVG path is the EXACT path that was stripped — same coordinates, same 1440×800 viewBox, so when overlaid it lands precisely where the cord would be in the full illustration.

**Cord animation** uses a `getTotalLength()` JS approach at the bottom of the IIFE script. **NOT** the `data-anim="draw-path"` system. Reason: `pathLength="1"` + `stroke-dasharray:1` is unreliable across Safari and some Chrome. The current pattern:

```js
var heroCord = document.getElementById('hero-cord');
if (heroCord) {
  var len;
  try { len = heroCord.getTotalLength(); } catch (e) { len = 3000; }
  if (!len || isNaN(len)) len = 3000;
  heroCord.style.strokeDasharray  = len;
  heroCord.style.strokeDashoffset = len;
  requestAnimationFrame(function () {
    requestAnimationFrame(function () {
      heroCord.style.transition = 'stroke-dashoffset 2400ms cubic-bezier(0.22, 1, 0.36, 1) 400ms';
      heroCord.style.strokeDashoffset = '0';
    });
  });
}
```

If the new chat needs to animate another SVG path, **use this same pattern** — not the `data-anim="draw-path"` primitive.

### Hero text content
- Eyebrow: `Critical Connections`
- Headline: `The Power of Free` on ONE line — `<em>Power</em>` is Concrette italic, **coral** (`var(--warm-coral)`), not plum

- Buttons: coral `Read the Report` (left) → `#aboutreport`; plum `Watch the Story` (right) → `#hero-video`. Both square corners, no arrows.

## 5. Global decisions / standing rules

These took multiple rounds to land. **Do not undo without explicit approval.**

### Margins
- `--gutter: clamp(20px, 5vw, 71px)` — side margin to text on either side. Hits 71px on viewport ≥ 1420px.
- `--top-pad: clamp(96px, 16vh, 151px)` — top padding for sections. Hits 151px on viewport ≥ 945px tall.
- Applied to every section. Exceptions: header, findings intro, take action, methodology — illustrations bleed to edge, only text respects gutter.

### Eyebrow style — flat text, NEVER pills
Client (Worth Rises) explicitly rejected the rounded pill / bordered eyebrow on 2026-04-29. All eyebrows are flat uppercase bold (13px / weight 700 / 0.16em letter-spacing). No `border`, no `border-radius`, no `padding`. Saved as feedback memory: `feedback-eyebrow-no-pill.md`.

### Sub-nav (findings)
- Lives **outside** `.findings-wrap` as a sibling — `position: fixed; bottom: 0`, slides up via `transform: translateY(100%) → translateY(0)` when user enters Findings Intro.
- Active tab tracking via scroll position (NOT IntersectionObserver thresholds — those failed when sections are taller than viewport). Trigger line at 80% of viewport height. The last finding whose top crossed below the trigger line wins.
- Click-to-scroll uses `headerH + 1` as the scroll offset target, accounting for sticky header.

### Anchor scroll targets
`scroll-margin-top: var(--header-h)` applied globally to `#aboutreport`, `#findings`, `#actions`, `#aboutproject`, `#hero-video` so nav links land flush with section top instead of half-hidden under the sticky header.

### Always save backups before edits
Scott's standing rule. `index.backup-2026-04-28-pre-rebuild.html` is the most recent.
